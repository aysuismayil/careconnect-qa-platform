# Test Cases — Caregiver Profiles

Covers profile creation, editing, photo upload, certifications, and public profile display. See [template](../templates/test-case-template.md).

| ID | Title | Preconditions | Test Data | Steps | Expected Result | Priority | Type | Platform |
|---|---|---|---|---|---|---|---|---|
| TC-PROF-001 | Create profile with all required fields | New caregiver account, no profile yet | Bio (150 words), 1 service, hourly rate $25, availability set | Complete onboarding form, submit | Profile created and marked "Live"/visible in search | P0 | Positive | Web/Mobile |
| TC-PROF-002 | Profile cannot go live with required fields missing | New caregiver account | Bio left blank | Attempt to publish profile without bio | Inline validation error; profile stays in "Draft"/incomplete, not visible in search | P0 | Negative | Web/Mobile |
| TC-PROF-003 | Upload valid profile photo | Existing profile | JPEG, 2MB, 1080x1080 | Upload photo via profile editor | Photo uploads, displays correctly cropped/resized on profile and search cards | P1 | Positive | Web/Mobile |
| TC-PROF-004 | Reject oversized photo upload | Existing profile | File: 25MB PNG (assume 10MB limit) | Attempt upload | Inline error stating size limit; upload rejected, no partial/corrupt file saved | P2 | Negative | Web/Mobile |
| TC-PROF-005 | Reject non-image file disguised with image extension | Existing profile | `malware.exe` renamed to `photo.jpg` | Attempt upload | Upload rejected after real content-type validation (not just extension check); no file processed | P1 | Negative/Security | Web |
| TC-PROF-006 | Edit and save bio text | Existing profile | Updated bio text, 500 chars | Edit bio, save | Change persists after page refresh/app restart; reflected on public profile | P1 | Positive | Web/Mobile |
| TC-PROF-007 | Bio respects max character limit | Existing profile | Bio text of 5,000 characters (assume 1,000 limit) | Enter text exceeding limit | Input blocked/truncated at limit with visible counter; no silent data loss on save | P2 | Boundary | Web/Mobile |
| TC-PROF-008 | Add multiple services with individual rates | Existing profile | Elder Care $30/hr, Pet Care $18/hr | Add two services with distinct rates | Both services saved and shown separately on public profile and in search filtering | P1 | Positive | Web/Mobile |
| TC-PROF-009 | Remove a service from profile | Profile with 2+ services | Remove "Pet Care" | Delete one service | Service removed from profile; caregiver no longer appears in "Pet Care" filtered search | P1 | Positive | Web/Mobile |
| TC-PROF-010 | Certification upload and "Verified" badge display | Existing profile, admin verification step exists | Certification PDF | Upload certification document | Shows "Pending verification" until admin approves; badge only appears after verification, not immediately on upload | P1 | Positive | Web |
| TC-PROF-011 | Public profile hides sensitive info from unauthenticated/other-role viewers | Public profile view | Caregiver's phone/email in profile settings | View caregiver profile as a logged-out visitor or as another caregiver | Direct contact info (phone/personal email) is NOT shown publicly; only in-platform messaging/booking is exposed | P0 | Security/Negative | Web/Mobile |
| TC-PROF-012 | Availability calendar reflects real-time booking status | Caregiver has an upcoming confirmed booking | Booked slot: Sat 2–4 PM | View caregiver's public availability calendar | The booked slot shows as unavailable to other customers immediately after confirmation | P0 | Positive | Web/Mobile |
| TC-PROF-013 | Caregiver can pause/deactivate profile visibility | Active, live profile | — | Toggle "Pause my profile" | Profile immediately stops appearing in search results (see [TC-SRCH-017](02-search-filtering-test-cases.md)); existing confirmed bookings unaffected | P1 | Positive | Web/Mobile |
| TC-PROF-014 | Profile edits mid-review don't affect an in-progress customer booking flow | Customer viewing caregiver profile in checkout | Caregiver edits rate mid-checkout | Caregiver changes hourly rate while a customer is mid-checkout on the old rate | Customer's checkout either locks the rate at time of slot-hold, or clearly re-displays updated price before payment — price shown must never silently differ from price charged (see [BUG-005](../bug-reports/BUG-005-price-mismatch-frontend-backend.md)) | P0 | Edge | Web |
| TC-PROF-015 | Star rating average updates after a new review | Profile with existing reviews and average rating | New 5-star review submitted | Customer submits a review after a completed booking | Average rating recalculates correctly and updates on profile/search cards | P2 | Positive | Web/Mobile |
